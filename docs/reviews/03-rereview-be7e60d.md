### R2 재현 순서

1. 작업 상세를 연다. 설명은 A다.
2. 다른 탭/클라이언트를 모사해 API로 같은 작업의 설명을 B로 변경한다.
3. 첫 화면에서 **제목만** 수정·저장하면 409가 발생한다.
4. 충돌 안내를 확인하고 ‘다시 저장’을 누른다. 제목은 저장되고 서버 설명 B는 아직 유지된다.
5. **설명을 입력하거나 수정하지 않고**, 설명 칸을 focus → blur 한다.
6. 200 PATCH가 발생하고 서버 설명이 B에서 A로 되돌아간다.

실제 첫 실행:

```json
{
  "initialUi": "동시 실패 후 중요한 설명",
  "external": "외부에서 갱신한 최신 설명 3",
  "serverBeforeFocus": "외부에서 갱신한 최신 설명 3",
  "uiBeforeAndAfterFocus": "동시 실패 후 중요한 설명",
  "focusBlurPatchStatus": 200,
  "serverAfterFocus": "동시 실패 후 중요한 설명"
}
```

두 번째 실행도 외부 설명의 버전 표기만 6으로 달랐고, 동일하게 A로 덮어썼다.

### R2 원인과 테스트 공백

`applyKeepDrafts`는 `t`와 `tRef`는 갱신하지만 `title`·`desc`는 모두 보존한다. 실제 편집 중인 초안과 단순히 오래된 화면값을 구별하지 않는다. 이후 `onBlur`는 `desc !== t.description`을 사용자 변경으로 간주하고 최신 버전으로 PATCH하므로, 서버 충돌 방어에도 걸리지 않는다.

추가된 외부 수정 E2E는 제목 재시도 직후 서버 설명이 B인지까지만 검사한다. 그 다음 미수정 필드에 포커스를 넣었다 빼는 경로를 추가해야 한다. 실제 편집한 설명 초안은 충돌 후에도 보존돼야 하므로, 모든 입력창을 무조건 최신값으로 덮는 방식도 피해야 한다.
