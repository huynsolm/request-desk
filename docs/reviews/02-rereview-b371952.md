## 잔여 발견 R1 — F2: 복수 필드 재시도에서 실패가 숨겨짐

### 재현

1. 작업 상세에서 PATCH 요청이 실패하도록 네트워크 장애를 설정한다.
2. 제목을 변경하고 포커스를 옮겨 저장을 실패시킨다.
3. 설명도 변경하고 포커스를 옮겨 저장을 실패시킨다.
4. 네트워크 장애를 해제하고 **‘다시 저장’을 한 번** 누른다.
5. 제목 PATCH는 200, 이어지는 설명 PATCH는 409가 된다.
6. 설명 초안은 화면에 남지만 서버에는 이전 설명이 남는다. 저장 실패 배너와 재시도 버튼은 사라진다.

두 번의 실제 결과:

```json
{
  "statuses": [200, 409],
  "serverTitle": "동시 실패 후 제목",
  "serverDesc": "요청 ‘추가 재검수’에서 확정한 요구사항 ‘예약 날짜 조회’을 구현해요.",
  "uiDesc": "동시 실패 후 중요한 설명",
  "retryButtons": 0
}
```

즉, 이번에는 초안이 즉시 지워지지는 않는다. 하지만 저장되지 않은 사실을 알리는 표시가 없어 사용자가 완료된 것으로 오인할 수 있고, 새로고침·화면 이탈 시 서버에 저장되지 않은 설명을 잃게 된다.

### 원인

- `applyKeepDrafts`는 `setT(d)`만 호출한다. `tRef.current`는 다음 렌더에서 갱신된다.
- `useSaver.retry()`는 대기 작업을 `await`로 연속 실행한다. 첫 응답 후 React가 재렌더하기 전에 다음 작업이 실행될 수 있어, 설명 요청이 이전 `version`을 사용한다.
- 기본 재시도 함수는 `track(key, fn, onOk)`만 재호출한다. `save()` 바깥의 `afterFailure`는 재실행하지 않는다.
- 409는 retryable이 아니므로 대기열에서 삭제되고, 큐가 비면 저장 실패 표시도 해제된다. 실패 결과를 `retry()`가 사용자에게 전달하지 않는다.

### 수정 방향

- 성공 응답 적용 시 다음 저장이 즉시 참조할 서버 상태·버전도 함께 갱신한다. React 렌더 완료 시점에 최신 버전 전달을 의존하지 않도록 한다.
- 최초 저장과 재시도가 같은 오류 처리 경로를 거치게 한다. 충돌 시 사용자 초안과 실패 표시를 유지하고, 최신 서버 상태 확인 후 명시적으로 다시 저장할 수 있게 한다.
- 회귀 테스트에 **제목·설명 모두 실패 → 한 번에 재시도**를 추가한다. 화면 입력값만 확인하지 말고 서버의 두 필드와 응답 상태를 확인한다.
- 제목·설명·상태 세 개의 대기 작업, 반복 재시도, 실제 외부 수정으로 인한 409도 함께 확인하는 것이 좋다.
