# Handoff: 리퀘스트 데스크 (Request Desk)

## Overview
웹 제작·개발 담당자 1인이 고객의 모호한 요청(메신저·이메일)을 붙여 넣고, AI 제안을 바탕으로 **요구사항 → 확인 질문 → 미확정 사항**으로 정리·검토·확정한 뒤, 확정된 요구사항을 **작업**으로 만들어 진행 상태를 관리하는 업무용 웹앱.

핵심 원칙: **고객이 말한 사실(원문) / AI의 해석(제안) / 사람이 확정한 내용**을 화면에서 항상 구분한다.

범위 밖(만들지 말 것): 로그인, 채팅, 결제, 견적, 음성 입력, 외부 서비스 연동. 결제·로그인·알림은 샘플 요청에서 확정되지 않았으므로 확정 기능이나 작업에 넣지 않는다.

## About the Design Files
이 폴더의 파일은 **HTML로 만든 디자인 레퍼런스(동작하는 프로토타입)**이며, 그대로 배포할 프로덕션 코드가 아니다. 대상 코드베이스의 기존 환경(React, Vue 등)과 패턴으로 **다시 구현**하는 것이 과제다. 기존 환경이 없다면 React + TypeScript(예: Vite 또는 Next.js)를 권장한다.

- `request-desk-v2.dc.html` — **기준 디자인(최신)**. 브라우저에서 바로 열린다(같은 폴더의 `support.js` 필요). 템플릿은 `<x-dc>` 안의 HTML(인라인 스타일), 로직은 하단 `<script data-dc-script>`의 `class Component` 안에 있다. 상태 구조·샘플 데이터·전이 로직을 그대로 참고하면 된다.
- `reference/request-desk-v1.dc.html` — 이전 버전(요청 상세 개선 전). 비교용, 구현 대상 아님.

AI 연결은 없다. 프로토타입은 고정 샘플 분석 결과를 1.8초 지연 후 돌려준다. 실제 구현에서는 분석 API로 교체하되 **아래 응답 형태와 상태 흐름은 유지**한다.

## Fidelity
**High-fidelity.** 색상·타이포·간격·상태·문구가 최종안이다. 픽셀 단위로 재현하되 코드베이스의 기존 컴포넌트/라이브러리를 사용한다. 모든 사용자 문구는 이 문서와 HTML의 한국어 문구를 그대로 쓴다.

기준 해상도: 데스크톱 1440px. 최소 폭 1200px(`min-width:1200px`).

| 상태 | 현재 단계 | 안내문 | 버튼 |
|---|---|---|---|
| 분석 전(idle) | 1 | AI가 원문을 요구사항·질문·미확정 사항으로 나눠 제안해요. 제안은 자동으로 확정되지 않아요. | Primary "요청 분석하기" |
| 분석 중(loading) | 1 | 원문을 분석하고 있어요. 그동안 원문을 계속 읽을 수 있어요. | Disabled 스피너+"분석 중…" |
| 분석 실패(error) | 1 | 분석에 실패했어요. 원문은 그대로 남아 있어요. | Primary "다시 시도" |
| 검토 중, 검토 전 항목 N>0 | 2 | 검토 전 AI 제안이 N개 남아 있어요. 모두 검토해야 확정할 수 있어요. | Disabled "검토 완료하고 확정" |
| 검토 중, 요구사항 0개 | 2 | 확정할 요구사항이 없어요. 요구사항을 추가해 주세요. | Disabled "검토 완료하고 확정" |
| 검토 중, 모두 검토함 | 2 | 확정하면 요구사항이 고정돼요. 작업은 다음 단계에서 따로 만들어요. | Primary "검토 완료하고 확정" |
| 확정, 선택 n>0 | 3 | 작업으로 만들 요구사항을 선택하세요 · n개 선택됨 | 텍스트 "다시 검토하기" + Primary "작업 만들기 (n)" |
| 확정, 선택 0 | 3 | 작업으로 만들 요구사항을 하나 이상 선택해 주세요. | 텍스트 "다시 검토하기" + Disabled "작업 만들기" |
| 확정, 모든 요구사항 작업화 | 모두 ✓ | 모든 요구사항을 작업으로 만들었어요. | 텍스트 "다시 검토하기" + Secondary "작업 목록 보기" |

**저장 / 확정 / 작업 만들기는 서로 다른 행동이다.**
- 저장: 자동. 모든 편집 직후 백그라운드 저장. UI는 상태 텍스트만.
- 확정: 요청 상태를 `확정`으로 바꾸고 분석 항목 편집을 잠근다. 작업은 만들지 않는다.
- 작업 만들기: 확정 후 선택한 요구사항으로 확인 모달을 거쳐 작업을 생성.

## Interactions & Behavior 요약
1. 요청 등록 → 상세(상태 `접수`, 분석 전)
2. "요청 분석하기" → loading(프로토타입 1.8s) → 성공: 분석 결과 표시, 요청 상태 `검토 중` / 실패: error 상태, 원문·편집 내용 유지, "다시 시도"
3. 각 AI 항목: "검토함으로 표시" 또는 수정(수정 시 `담당자 수정` + 검토 완료 처리) 또는 삭제(되돌리기 가능). 추가한 항목은 `담당자 추가`, 검토 완료로 간주.
4. 검토 전 항목 0개 & 요구사항 ≥1 → "검토 완료하고 확정" 활성 → 상태 `확정`, 편집 잠금, 작업 미생성 요구사항 전부 기본 선택, 토스트 "요구사항을 확정했어요. 작업은 아직 만들어지지 않았어요."
5. "다시 검토하기" → 상태 `검토 중`, 선택 해제, 편집 잠금 해제
6. 요구사항 선택 → "작업 만들기 (n)" → 확인 모달에서 제목·완료 조건 수정 → 생성
7. 작업 상태 변경(목록 select 또는 상세 세그먼트), 설명·완료 조건 편집
8. 작업 ↔ 요청 양방향 이동

**절대 자동으로 하지 않을 것**: 분석 후 자동 확정, 자동 작업 생성, 질문·미확정 사항을 작업에 포함.

**저장**: 분석 항목 편집·확정·작업 생성 등 요청 데이터 변경마다 자동 저장(프로토타입은 700ms 후 성공/실패). 실패 시 클라이언트 상태를 버리지 말 것(낙관적 업데이트 유지 + 재시도).

**애니메이션**: 스피너만(14×14, 2px 보더 `#d3d6f3` + 상단 `#4447a8`, 0.8s linear 회전). 원문 하이라이트 background transition .15s. 그 외 없음.

## State Management
```ts
type RequestStatus = '접수' | '검토 중' | '확정';
type TaskStatus = '할 일' | '진행 중' | '완료';
type Origin = 'ai' | 'edited' | 'added';

interface AnalysisItem {
  id: string;
  text: string;
  source?: string;   // 요구사항: 원문 근거(원문에 그대로 존재하는 부분 문자열)
  note?: string;     // 질문/미확정: AI 해석
  origin: Origin;
  reviewed: boolean; // origin==='ai'일 때 검토 여부
  taskId?: string | null; // 요구사항 → 생성된 작업
}
interface Analysis { reqs: AnalysisItem[]; questions: AnalysisItem[]; unknowns: AnalysisItem[]; }
interface Request {
  id: string; title: string; client: string; raw: string; date: string;
  status: RequestStatus;
  analysisState: 'idle' | 'loading' | 'error' | 'done';
  analysis: Analysis | null;
}
interface Task {
  id: string; title: string; requestId: string; reqText: string;
  status: TaskStatus; description: string;
  criteria: { id: string; text: string; done: boolean }[];
}
```
UI 상태: `view`, `reqId`, `search`, `filter`, `panel`(새/수정 폼 + errors/saving/error), `editing`({sec,id,text,isNew}), `selected`(요구사항 id → bool), `modal`(작업 초안), `taskFilter`, `taskId`, `save`('saved'|'saving'|'error'), `hoverSrc`, `toast`.

파생값: 검토 전 개수 = `origin==='ai' && !reviewed` 항목 수(세 영역 합).
