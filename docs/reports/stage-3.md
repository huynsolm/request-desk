# 3단계 보고서 — 실제 AI 연결 (Anthropic Claude API)

브랜치 `stage-3-ai-provider` · 상태: **구현 완료, 독립 검수 대기** (`main` 미병합)

## 사용자가 정한 것 (2026-10-21)
- 제공자: Anthropic Claude API · 인증: 서버 전용 `.env` 키 · 비용 상한: 하루 20회 / 한 달 300회

## 구현한 것
| 영역 | 내용 |
|---|---|
| 제공자 | `server/analysis/anthropic.ts` — 공식 SDK, 구조화 출력 요청, 응답은 JSON 해석만 하고 검증은 2단계 서버 검증(엄격 zod + 항목별 규칙 + 원문 근거)을 그대로 통과해야 저장 |
| 키 | `.env`(서버 전용, `process.loadEnvFile`) / 환경 변수. 키가 없으면 `ai` 시작 거부. 응답·로그·기록에 키·제공자 원문 오류 없음 |
| 전송 | 요청 **원문만**(제목·고객명 제외), 무작위 경계 문자열로 감싸 지시문 주입을 데이터로 취급 |
| 한도 | `startAnalysis` 가 하루/한 달 호출 수를 DB 로 세어 서버에서 429 `usage_limit` (실패한 호출도 셈, 외부 호출 없음) |
| 사용량 기록 | 마이그레이션 `0004_analysis_usage.sql` — `model`, `input_tokens`, `output_tokens` |
| 오류 | 키/한도/모델/네트워크/장애/결제/거절/잘림/형식/시간 초과를 안전한 문구로 구분 |
| 화면 | 전송 안내, 사용량(`오늘 N/20 · 이번 달 N/300`), 한도 도달 시 버튼 비활성, 재분석 확인창에 전송·호출 안내 |
| 도구 | `npm run test:e2e:ai`(가짜 서버), `npm run ai:smoke`(실제 호출 1회, 사용자가 직접) |

## 미검증 (통과했다고 쓰지 않음)
- **실제 Anthropic 서버와의 통신**: 키가 없어 호출하지 않았다. 사용자가 `.env` 에 키를 넣고 `npm run ai:smoke` 로 확인해야 한다(호출 1회 비용).
- 실제 응답 품질(원문 인용을 글자 그대로 복사하는지, 원문에 없는 기능을 넣지 않는지)과 실제 비용.
- 실제 429/과부하 때의 재시도 지연, 큰 원문(2만 자)에서의 실제 소요 시간.
- 모델 이름 `claude-opus-5-5` 와 `output_config.format`(구조화 출력)의 실제 서버 수락 여부 — 스모크에서 거부되면 `ANTHROPIC_MODEL` 변경 또는 수정이 필요할 수 있다.

## 알려진 한계 / 결정
- 상한은 **횟수**이며 금액 상한이 아니다. SDK 자동 재시도(1회)는 같은 호출로 센다. 서버 PC 시계를 바꾸면 우회된다(로컬 개인용).
- 서버 쪽 모델 fallback 은 쓰지 않았다(비용·기록 예측 불가).
- 제공자 쪽에서 원문을 어떻게 보관·사용하는지는 Anthropic 약관/설정에 따른다(앱이 통제하지 못함).
